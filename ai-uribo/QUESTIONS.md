## Q4. Webhookの署名検証と、スタッフ登録の方法 【技術的制約・運用が1つ変わります】

- **GASのウェブアプリはHTTPヘッダーを読めないため、LINE標準の `X-Line-Signature` 検証はGAS単体では不可能**です
- 代わりに次の3段構えにしました（別AIレビューの指摘を受けて強化済み）
  1. Webhook URLに秘密キーを付ける（`?k=＜WEBHOOK_SECRET＞`）。不一致は破棄。**未設定なら全拒否**
  2. スタッフ登録は**8桁の登録コード方式**（管理者が本人にだけ伝える・使い捨て・既存紐付けは上書き不可）
  3. S1で有効=TRUEかつ紐付け済みのユーザー以外は操作を受け付けない
- 署名検証関数 `validateSignature_()` は実装済みで、将来プロキシ等を挟めばそのまま有効になります
- **お願い：`WEBHOOK_SECRET` を必ず設定し、URLを外部に貼らないでください**
- **お願い：S1の「登録コード」列の値を本人にだけ個別にお伝えください**（グループには流さない）
- 変更箇所：`src/webhook.gs` の `verifyRequest_()` / `tryRegisterByCode_()`
- 経緯と理由：`docs/レビュー対応ログ.md`

## Q7. 既存Netlifyアプリの LINE ログインが 400 になる件（AI Uriboとは別件）

`melodious-puppy-b420fc.netlify.app` で
**「400 Bad Request / This channel is now developing status. User need to have developer role.」**
が出ています。これはアプリの不具合ではなく、**LINEチャネルの公開設定**です。

- LINE Developers → 該当の **LINEログインチャネル** → 「チャネル基本設定」
- **ステータスが「開発中（Developing）」**になっています。この状態では、
  そのチャネルの**開発者・テスターに登録された人しかログインできません**
- 直し方は2つ
  1. **公開する**：チャネルのステータスを「公開済み（Published）」に切り替える（全員ログイン可）
  2. **テスターに追加する**：試すだけなら、その人を開発者/テスターとして権限追加
- なお、このアプリが表示しているID（`U…`）は**LINEのユーザーID**で、
  AI UriboがS1に持つ `line_user_id` と**同じ値**です。将来1つの登録で両方に通せます

### 玉里のネットワーク（2026-08-13 現地確認）

| 機器 | アドレス | 備考 |
|---|---|---|
| AIハブ（HA / OpenClaw / Frigate） | `192.168.1.13` | Wi-Fi `pr500k-d091b4-3` 接続。**有線化できる**（アプリに案内あり）<br>Wi-Fi MAC `B0:E9:FE:C9:CC:CB` ／ BLE MAC `B0:E9:FE:B6:C2:4C` |
| キッチンカメラ Pan/Tilt Cam Plus 3K FB | `192.168.1.22` | Wi-Fi `pr500k-d091b4-1`（2.4GHz帯）・**信号強度43%** |

- ⚠ **IPは固定されていない**（DHCP）。停電・再起動で `.22` や `.13` が変わると連携が黙って止まる。

## Phase2を始めるときに必要なこと

利用者の登録はメニューからできるようになりました（コード修正は不要）。

1. メニュー「AI Uribo」→「**利用者を登録する**」で、拠点と氏名を1人ずつ入力
   （氏名はS9対応表にだけ入り、他のシートには記号だけが残ります）
2. 自動データを使う利用者は、S2の **服薬自動／在否自動／日中自動** をTRUEに
3. メニュー「**支援記録の質問を開始する（Phase2）**」を実行
4. 余裕があれば「**シフト表を取り込む**」（夜勤担当者の質問が消えます）

まだ確認が必要なのは次の2点です。

- 個別支援記録システム側の**項目名の正確な表記**（S3の項目名を一字一句合わせると、
  既存アプリへの取り込みがそのまま通ります）
- SwitchBot以外の自動ソース（ラボ出勤・猪ノ屋日誌）の**受け渡し方法**
  （形式は `docs/自動ソース取込フォーマット.md` のとおりで、S4に入れば動きます）

## 決めた既定値（変えたいときはS8設定を書き換えるだけ）

コード修正なしで調整できます。運用しながら合わなければ数字だけ直してください。

| 設定キー | 既定 | 意味 |
|---|---|---|
| `learn_min_samples` | 8 | 何回突き合わせたら「自動確定」に上げてよいか |
| `learn_promote_rate` | 0.9 | この正答率以上で質問をやめる |
| `learn_demote_rate` | 0.6 | これを下回ったら聞き直しに戻す |
| `learn_spotcheck_every` | 20 | 自動確定でも何件に1回は抜き打ちで聞くか |
| `remind_after_hours` | 20 | 返事が無い確認を何時間後にもう一度送るか |
| `remind_max` | 2 | 送り直しの上限（超えたら催促せず週次で社員へ） |
| `archive_after_days` | 180 | 何日過ぎた行を「_保管」シートへ移すか |
| `log_keep_days` | 90 | 実行ログを何日分手元に残すか |
| `max_items_per_message` | 3 | 1通に載せる確認の最大件数（多いと感じたら減らす） |
| `test_mode` | FALSE | TRUEの間はLINEに送らず記録だけ（設定作業中の誤送信防止） |

コード側で決めた値（変えるなら一行修正）：

- **訂正できる期間：3日**（`correct.gs CORRECT_WITHIN_DAYS`）
- **バッチの時間予算：4分**（`batch.gs BATCH_TIME_BUDGET_MS`。GASの6分制限の手前で切り上げる）

## お願い（運用でこれだけ守っていただきたいこと）

1. **拠点名の書き方をそろえてください。** S2_利用者マスタ・S11_勤務予定・S12_機器マスタで
   「清水」と「うりぼベース清水」が混ざると、シフトの夜勤がどの拠点か分からなくなり、
   機器も利用者に結びつきません。ゆれがあれば自己点検がLINEでお知らせします
2. **`WEBHOOK_SECRET` は必ず設定し、URLを外部に貼らないでください**（未設定なら全拒否になります）
3. 既存アプリと連携する場合は `API_SECRET` を設定してください（未設定なら `WEBHOOK_SECRET` を使います）
