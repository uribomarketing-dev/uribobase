# 自動ソース取込フォーマット（【08】第4章）

**原則：帳簿の隙間は、手元のデータで積極的に埋める。推定は「要精査」の印を付けて人が精査する。**
（AI Uriboは記録を正しく作る装置ではなく、実態を素早くつかむための補助です）
各アプリ・センサーからのログは、S4_実績ログ取込 に「生ログ」として1行ずつ入れれば、
毎朝10:00の `runAutoFill()` が支援記録の項目名に変換して自動充足します。
人への質問は、変換できなかった分だけになります。

## 生ログの入れ方（S4に追記するだけ）

| 列 | 入れる値 |
|---|---|
| log_id | 空でよい（手動なら任意の一意な値） |
| 発生日 | `2026-08-11` 形式 |
| 対象種別 | 下表の「対象種別」 |
| 対象 | user_code（例：`SMZ01`）。全体の情報は `ALL` |
| 項目名 | 下表参照 |
| 値 | 実測値（あれば） |
| 取込元 | 送り元アプリ名（任意） |
| 取込日時 | `2026-08-12 07:30` 形式 |

## 対応表

| 自動ソース | 対象種別 | 項目名の例 | 変換後（S4に自動追記される項目） | 必要な利用者フラグ |
|---|---|---|---|---|
| SwitchBot服薬ログ | `raw_switchbot` | `服薬` | 服薬ボックス開放（事実）＋**服薬確認（推定・要精査）**。値に時刻を入れておくとそのまま残る | S2「服薬自動」=TRUE |
| 開閉センサー | `raw_door` | `開閉` / `夜間開閉` | 在否確認（事実）＋夜間の動き（事実）＋**夜間巡回・就寝確認（推定・要精査）** | S2「在否自動」=TRUE |
| うりぼラボ出勤 | `raw_labo` | `出勤` | 在否確認＝在宅（ラボ出勤記録より）／日中活動＝ラボ出勤 | S2「日中自動」=TRUE |
| 猪ノ屋業務日誌 | `raw_inoya` | `天気` / `献立` | そのまま転記（対象=`ALL`可）＋献立があれば**食事提供（推定・要精査）を全利用者に展開** | 不要 |
| 前夜に聞いた予定 | `plan`（自動生成） | `予定_外出` など | 翌日の**実績を推定**（外出なし・帰省・ラボ出勤・食事提供／要精査） | 不要 |
| **AIハブ（OpenClaw）の映像解析** | `raw_openclaw` | S3の項目名そのまま | 同じ項目を**推定で充足**（要精査）。下記のPOSTで受け取る | 不要 |

- 変換結果は S4（記録として成立）と S7補完台帳（既存アプリへの還元用）の両方に書かれます
- **推定で埋めたものは S7補完台帳の「要精査」列が TRUE になります。**
  社員がLINEで `精査` と送ると一覧が返るので、違っていればS7で値を直し、要精査をFALSEにしてください
- 推定をやめたいときは S8設定の `autofill_estimate` を FALSE にすると、事実のログだけになります
- 同じ日・同じ対象・同じ項目のログが既にある場合は二重に書きません
- S2の自動フラグがFALSEの利用者は自動充足せず、LINEで人に確認します
  （清水では川口様・中野様が自動データ非対応のため、この2名が確認の中心になります）

## 新しい自動ソースを足すとき

`src/autofill.gs` の `AUTOFILL_SOURCES` 配列に1件追加するだけです。

```js
{
  id: 'new_source',          // 取込元として記録される名前
  生ログ種別: 'raw_new',      // S4の対象種別
  必要フラグ: '在否自動',      // S2の列名（不要なら空文字）
  説明: '何を埋めるか',
  map: function (raw) {
    return [{ 項目名: '在否確認', 値: '在宅（新ソース）' }];
  }
}
```

## 自動データを「判断材料」として質問に添える（参照ログ）

S3チェック項目マスタの **「参照ログ」列**にS4の項目名を書くと、その自動ログが質問の直前に
「（参考）〜」として届きます。自動データを記録の代わりにせず、人が判断するための材料として
見せるための仕組みです。服薬確認（CHK106）が `服薬ボックス開放` を参照する設定になっています。

## 外部から観察を投入する（AIハブ／OpenClaw・他アプリ共通）

AI UriboのWebhook URL（`?k=` 付き）に、次の形でPOSTすると S4 に取り込まれます。
**画像・映像は受け取りません。言葉だけです。**

```json
{
  "source": "openclaw",
  "observations": [
    { "date": "2026-08-11", "target": "SMZ01", "item": "服薬確認",
      "value": "食後に服薬している様子（キッチンカメラ 08:12）" },
    { "date": "2026-08-11", "target": "ALL", "item": "食事提供",
      "value": "夕食を配膳（18:05）" }
  ]
}
```

| 項目 | 内容 |
|---|---|
| `source` | 送り元の名前（`openclaw` など）。S4の対象種別が `raw_<source>` になります |
| `date` | 対象日。省略すると当日 |
| `target` | `user_code`、または拠点全員なら `"ALL"` |
| `item` | S3チェック項目マスタの**項目名と一致させる**と、その質問が出なくなります |
| `value` | 観察内容。300文字まで |

応答は `OK:<取り込み件数>`。翌朝の自動充足で「推定（要精査）」として記録に反映されます。

## 予定ログ（明日の予定）

夜21:00の確認セットで答えた「明日の予定」は、S4に `対象種別=plan` として保存されます。
翌日の不足判定はこの予定と実績を突き合わせるため、**予定を答えるほど翌日の質問が減ります**。
`予定_帰省=あり` の日は、その利用者のその日の全項目が判定除外になります。
