# 不具合が出たときの伝え方（1枚）

AI Uriboの調子がおかしいときは、**次の3つを送るだけ**で調査できます。
原因を推測して書く必要はありません。

---

## ステップ1：何が起きたかを1〜2行

例：

- 「今朝10時の質問が誰にも届かなかった」
- 「ボタンを押したのに『記録に反映しました』が返ってこない」
- 「服部さんだけ質問が2回届く」

**いつ・誰に・何が** が分かれば十分です。

## ステップ2：診断情報を取る（どちらか一方でOK）

### 方法A：LINEで（早い）

AI Uriboに **`診断`** と送る（社員・管理者のみ）。
返ってきた文章をそのままコピーして渡してください。

### 方法B：スプレッドシートから（詳しい）

「AI_Uribo_台帳」を開く → メニュー **「AI Uribo」→「診断情報をコピー」** →
表示された全文をコピー。

> 診断情報に**氏名・LINE ID・回答の中身は含まれません**。
> 設定の状況、件数、直近のエラーだけが入ります。そのまま貼って構いません。

## ステップ3：エラーが出ていた時間帯が分かれば添える

スプレッドシートの **S10_実行ログ** を開き、
「結果」列が `エラー` になっている行の **日時・処理名・詳細** をコピー。
（診断情報にも直近20件は入るので、これは余裕があればで大丈夫です）

## 自分で先に試せる応急処置

| 症状 | まず試すこと |
|---|---|
| 質問が届かない | LINEで `状況` と送る → 反応がなければ `診断` |
| 「混み合っています」が続く | 1分待って再操作。それでも続くなら診断情報を送る |
| 誰かが登録できない | メニュー「AI Uribo」→「登録コードを発行」でコードを作り直して本人に渡す |
| 質問が多すぎる／少なすぎる | S3チェック項目マスタの「有効」列で項目をON/OFFできる（コード変更不要） |
| バッチの時刻を変えたい | S8設定の時刻を変更 → `installTriggers` を再実行 |
| とりあえず全部止めたい | GASエディタ左の時計アイコン（トリガー）で5本すべて削除。台帳のデータは残ります |

---

## 緊急停止のしかた（覚えておくと安心）

1. GASエディタを開く → 左メニューの**時計アイコン（トリガー）**
2. 一覧の各行の「⋮」→ **トリガーを削除**
3. これでLINEの自動送信は止まります（Webhookの返信は動いたままなので、
   完全に止めるならLINE Developersで「Webhookの利用」をオフ）
4. 再開するときは `installTriggers` を実行するだけ

データは消えません。困ったら**まず止めて、それから相談**で大丈夫です。
