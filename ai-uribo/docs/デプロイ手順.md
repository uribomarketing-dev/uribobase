# デプロイ手順（Step2〜Step5）

所要：30〜40分。上から順にそのとおり実行してください。

---

## 1. コードをGASプロジェクトに配置する

### 方法A：GASエディタに貼り付ける（clasp不要・推奨）

1. スプレッドシート「AI_Uribo_台帳」を開く → 拡張機能 → Apps Script
2. 既定の `コード.gs` を削除
3. 左の「ファイル」＋ボタンから **スクリプト** を追加し、`ai-uribo/src/` の **.gsファイルすべて** を1つずつ作る
   （ファイル名は拡張子なしで入力。20ファイルあります）

   `config` `db` `log` `notify` `setup` `users` `learn` `autofill` `shift` `consistency`
   `detect` `ask` `batch` `webhook` `api` `monthly` `selfcheck` `switchbot` `backup` `diagnose`

   > 順番はどれからでも構いません（GASは全ファイルをまとめて読み込みます）。
   > 1つでも抜けると「◯◯ is not defined」で止まるので、`ls ai-uribo/src/*.gs` の数と合っているか確認してください。
4. 各ファイルに対応する `.gs` の中身を全文コピーして貼り付け、保存
5. 左メニューの歯車（プロジェクトの設定）→「`appsscript.json` マニフェスト ファイルをエディタで表示する」にチェック
6. 現れた `appsscript.json` を `src/appsscript.json` の内容で置き換えて保存

### 方法B：claspを使う

```bash
npm install -g @google/clasp
clasp login
cd ai-uribo/src
clasp clone <スクリプトID>     # 既存プロジェクトに接続
clasp push                     # .gs をそのままpushできる
```

## 2. スクリプトプロパティを設定する（秘密情報）

GASエディタ → 左の歯車（プロジェクトの設定） → 下部「スクリプト プロパティ」→「スクリプト プロパティを追加」

| プロパティ名 | 値 |
|---|---|
| `LINE_CHANNEL_TOKEN` | LINE Developersで発行したチャネルアクセストークン（長期） |
| `LINE_CHANNEL_SECRET` | チャネル基本設定のチャネルシークレット |
| `WEBHOOK_SECRET` | 任意の推測されにくい文字列（例：`uribo-7f3k9x2m5q`）。**未設定だとWebhookは全リクエストを拒否します（安全側に倒すため）** |
| `WEBAPP_URL` | （任意）手順4で発行する `?k=` 付きのウェブアプリURL。SwitchBotのWebhook自動登録に使います |
| `SWITCHBOT_TOKEN` | （任意）SwitchBotアプリ → プロフィール → 設定 → アプリバージョンを10回タップ → 開発者オプション |
| `SWITCHBOT_SECRET` | （任意）同上のクライアントシークレット |

> 3つとも**藤原様ご自身が直接入力**してください。チャットや台帳に貼る必要はありません。
> `WEBHOOK_SECRET` はこの後のWebhook URLに付けるため、控えておいてください。

## 3. 台帳を初期化する

1. エディタ上部の関数選択で **`quickStart`** を選び「実行」
   （台帳の初期化＋**テストモードON**＋点検＋次にやることの一覧を、まとめて実行します）
2. 初回は認可ダイアログが出ます → アカウントを選択 → 「詳細」→「AI_Uribo（安全ではないページ）に移動」→ 許可
3. スプレッドシートに戻り、S1〜S13の13シートができていることを確認
4. S1に4名、S3にチェック項目、S8に設定値が入っていることを確認
   （更新でシートの列が増えた場合も、`quickStart` が既存シートに列を足すので作り直しは不要です）
5. **S1の兼崎様の氏名をフルネームに修正**してください

> **テストモードについて**
> `quickStart` は S8設定の `test_mode` を **TRUE** にします。
> この間はバッチを実行してもLINEには**実際には送られず**、送るはずだった文面がS6確認タスクに
> 「テスト」として残るだけです。設定作業中の誤送信を防ぐためです。
> 設定とテストがすべて済んだら、最後に **S8の `test_mode` を `FALSE`** に戻してください
> （現在の状態はメニュー「AI Uribo」→「設定を点検」や「診断情報をコピー」で確認できます）。

## 4. ウェブアプリとしてデプロイし、LINEに接続する

1. GASエディタ右上「デプロイ」→「新しいデプロイ」
2. 種類の選択（歯車）→ **ウェブアプリ**
3. 設定
   - 説明：`AI Uribo webhook v1`
   - 次のユーザーとして実行：**自分**
   - アクセスできるユーザー：**全員**（LINEサーバーからのアクセスに必要）
4. 「デプロイ」→ 表示された **ウェブアプリURL** をコピー
   （`https://script.google.com/macros/s/AKfy…/exec`）
5. URLの末尾に `?k=＜WEBHOOK_SECRETの値＞` を付ける
   例：`https://script.google.com/macros/s/AKfy…/exec?k=uribo-7f3k9x2m5q`
6. LINE Developers → 「うりぼシフト管理」チャネル → Messaging API設定
   - Webhook URL：上の**?k=付きURL**を貼る
   - 「検証」ボタンを押して成功することを確認
   - **Webhookの利用：オン**
7. LINE Official Account Manager → 応答設定
   - 応答メッセージ：**オフ**
   - Webhook：**オン**

> **署名検証についての注意**
> GASのウェブアプリはHTTPヘッダーを読めないため、LINE標準の `X-Line-Signature` 検証は
> GAS単体では実装できません（技術的制約）。本システムでは
> ①URLの秘密キー（`?k=`）が一致しないリクエストを破棄（**未設定時は全拒否**）
> ②登録コードを知っている本人しかスタッフとして登録できない
> ③S1で有効=TRUEかつ紐付け済みのユーザー以外は操作を受け付けない
> の3段構えで守っています。署名検証関数 `validateSignature_()` は実装済みで、
> 将来プロキシ等で署名を渡せる経路にした場合はそのまま有効になります。
> **`WEBHOOK_SECRET` は必ず設定し、URLを外部に貼らないでください。**

## 5. 登録コードでスタッフを紐付ける

**第三者が名前を選ぶだけでスタッフになりすませないよう、登録コード方式にしています。**

1. 台帳のS1「登録コード」列を開く（`initSheets()` が8桁のコードを自動発行しています）
2. コードを**本人にだけ**個別に伝える（LINEの個別トーク・口頭など。グループには流さない）
3. 本人が @462oxzee を友だち追加 → 案内に従ってコードをそのまま送信
4. 「○○さんですね。登録しました」と返り、S1のline_user_id列にIDが入る。**コードは自動で消えます**
5. 作り直したいとき（コードを失念・端末変更など）はメニュー「AI Uribo」→「登録コードを発行」

※すでに友だちの場合も、コードを送れば登録できます（友だち追加のやり直しは不要）
※すでに紐付いているスタッフに別の人がコードを送っても、上書きされません

## 6. トリガーを設定する

1. 関数 `installTriggers` を実行
2. 左メニューの時計アイコン（トリガー）で7件登録されていることを確認
   - `selfCheck` 毎日8時台（自己点検。消えたトリガーはここで自動的に入り直します）
   - `morningBatch` 毎日10時台
   - `nightBatch` 毎日21時台
   - `weeklyDigest` 毎週日曜10時台
   - `monthlyReport` 毎月1日11時台（前月の記録充足率）
   - `dailyBackup` 毎日3時台
   - `flushQueue` 毎日7時台
   （SwitchBotを設定している場合は `switchbotPoll` が加わり8件）
3. 関数 `checkSetup` を実行するとセットアップ状況が一覧で確認できます
   （スプレッドシートのメニュー「AI Uribo」→「セットアップ点検」でも可）

## 6b. SwitchBotをつなぐ（任意・機器がある拠点だけ）

1. `SWITCHBOT_TOKEN` / `SWITCHBOT_SECRET` / `WEBAPP_URL` をスクリプトプロパティに入れる
2. メニュー「AI Uribo」→「**SwitchBot機器を読み込む**」→ S12_機器マスタに機器が並ぶ
3. S12で **拠点・対象user_code・用途種別** を埋めて **有効=TRUE**（用途種別は
   服薬ボックス／玄関／居室ドア／人感／温湿度／施錠／家電／漏水 のいずれか）
4. メニュー「**SwitchBotのWebhookを登録**」→ 変化がその場で届くようになる
5. メニュー「**SwitchBotの状態を今すぐ取得**」で試し、S4に行が増えることを確認
6. `installTriggers` を再実行（毎朝9:00の取得トリガーが追加されます）

## 6c. 利用者を登録し、支援記録を始める

シフト希望の確認（Phase1）だけなら不要です。**日々の支援記録を埋めたい場合**に行います。

1. メニュー「AI Uribo」→「**利用者を登録する**」→ 拠点と氏名を入力（1人ずつ）
   - 氏名はS9_対応表にだけ入り、他のシートには記号（U001…）だけが残ります
2. 自動データを使う利用者は、S2_利用者マスタの **服薬自動／在否自動／日中自動** をTRUEに
3. メニュー「**支援記録の質問を開始する（Phase2）**」→ 優先度Aの項目が有効になります
4. メニュー「**シフト表を取り込む**」→ その月の夜勤を貼り付けておくと、
   毎日の「夜勤担当者は誰でしたか」を聞かれなくなります（記録には担当者名が残ります）

## 7b. 本番運用に切り替える（テストモードを解除する）

ここまでの設定と、`docs/テスト手順書.md` の実機テストが済んだら、最後に本番へ切り替えます。

1. スプレッドシートの **S8_設定** シートを開く
2. `test_mode` の行の値を **`FALSE`** に書き換える
3. メニュー「AI Uribo」→「設定を点検」で **テストモード：OFF** になっていることを確認
4. S6確認タスクに残っている送信状態「テスト」の行は、テスト中の記録です。消しても残しても動作に影響しません

> 逆に、設定をいじり直すときや大きくコードを更新したときは、
> 先に `test_mode` を `TRUE` に戻すと、現場に誤ってLINEが飛ぶことを防げます。

## 8. コードを更新したとき

コードを直しただけでは公開中のWebhookには反映されません。
**デプロイ →「デプロイを管理」→ 鉛筆アイコン → バージョン「新バージョン」→ デプロイ**
を実行してください。URLは変わりません（新規デプロイを作るとURLが変わるので注意）。
