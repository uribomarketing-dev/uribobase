## 1. 結論

**7件を修正済み・3件を要判断としてお預けします。** 項目の大きな抜けはありませんでしたが、
「記録として成立するか」の観点で**選択肢の粒度が足りない箇所**があり、そこを直しました。

## 2. 修正したこと（反映済み）

| # | 何が問題だったか | どう直したか |
|---|---|---|
| 1 | **食事提供が「提供した／提供なし」だけ**で、朝夕の別が残らない。食材料費の実費請求は提供実態と整合する必要があるのに、1日単位では根拠にならない | 選択肢を `朝夕とも提供 / 朝のみ提供 / 夕のみ提供 / 提供なし` に変更。「提供なし」は理由を一言求める |
| 2 | **夜間巡回が「実施した／未実施」だけ**で回数・時間帯が残らない。夜間支援の記録は「一晩に何回まわったか」が問われうる | 質問文に「22時〜5時」を明記し、選択肢を `複数回まわった / 1回まわった / できなかった / わからない` に変更 |
| 3 | **服薬が「実施した（記録漏れ）」の一択**で、自己管理の方と支援した方が区別できない | `声かけ・確認をした / 本人が自分で服薬 / 実施なし（一言記入） / わからない` に変更 |
| 4 | 質問文が「**〜の記録がありません**」という詰問調。毎日届くと責められている感じになり、回答率が落ちる | 「〜はいかがでしたか」「〜について教えてください」に統一 |
| 5 | 「**対応あり**」は現場語として曖昧（何に対する対応か分からない） | 「いつもと違う様子あり」に変更し、追記の案内を「**見たままを一言で**（例：37.5度の発熱、食事を残された）」に。推測ではなく観察事実が集まるようにした |
| 6 | **誰が支援し、誰が確認したかが分からない**。藤原様・服部様は2施設を回って紙台帳から移行中で、入力するのはお二人でも、実際に支援したのはその日の夜勤者。回答者＝支援者に見えてしまうと事実と違う | S7補完台帳に **「情報源」列**を追加し、`本人回答 / 支援担当者の記録（氏名） / 支援担当者：〇〇／管理者確認：〇〇 / 自動ログ（ソース名）` を自動で記録。さらに**その日の夜勤担当者を拠点ごとに1日1問だけ聞く**項目（CHK100）を新設し、その回答を同じ日の全記録の支援担当者名に反映する |
| 7 | **センサーの値が「実施した」と読める**。開閉センサーが示すのは「扉が開いた」事実であって、支援の実施ではない | 値を `服薬ボックスの開放を検知（SwitchBot自動記録）` `在室を検知（開閉センサー自動記録）` のように、**何の記録かが分かる表現**に変更。夜間の開閉は「夜間の動き」という別項目にし、**巡回の記録の代わりにはしない**（巡回は人が記録する） |

## 3. 要判断（藤原様＋新任のサービス管理責任者にお預けする3件）

### 判断1：服薬をセンサーで自動充足してよい利用者の範囲

【08】の方針どおり、SwitchBotの服薬ログでA6を自動充足する実装になっています。
ただし記録として求められるのは「**服薬支援を行ったこと**」であり、センサーが示すのは
「服薬ボックスが開いたこと」です。厳密には別のものです。

- **推奨**：S2利用者マスタの「服薬自動」をONにするのは、**自己管理で見守りのみの方**に限る
- 声かけ・手渡しなど**人の支援が入る方はOFF**にして、LINEで聞く（1タップです）
- どちらにするかは、個別支援計画の服薬に関する記載と揃えてください

### 判断2：A3「支援内容」とA4「利用者の状況」を両方毎日聞くか

記録としてはどちらも必要ですが、毎日2問は負担です。
「特記なし」「変わりなし」で1タップずつ終わる設計にはしてあります。

- **案A（現状）**：両方聞く。記録は最も厚くなる
- **案B**：A4だけ毎日聞き、「いつもと違う様子あり」のときだけA3を追加で聞く。質問が半分になる
- 案Bにする場合はS3のCHK103を無効にするだけで切り替えられます（コード変更不要）

### 判断3：夜勤者が誰だったかの記録

夜間支援の裏付けには、**シフト表・出退勤記録・支援記録の三つが一致していること**が見られます。
**対応済み**：紙台帳からの移行中という実態に合わせ、**その日の夜勤担当者を拠点ごとに1日1問だけ聞く**
項目（CHK100）を追加しました。朝の確認セットの1問目に出て、選択肢はS1の夜勤スタッフの氏名が
自動で並びます（該当者がいなければ「その他（名前を入力）」）。

- この1問への回答が、**同じ日・同じ拠点の全記録の「支援担当者」**として補完台帳に入ります
- 入力したのが藤原様・服部様であれば `支援担当者：〇〇／管理者確認：藤原寛` の形で両方残ります
- 1日1タップ増えるだけで、「誰が支援し、誰が確認したか」が記録として成立します
- Stage2でシフトアプリのCSVをS11に取り込めば、この1問も自動で埋まり質問が消えます

**残る判断**：この項目を有効にするタイミング（紙台帳からの移行が済むまでは有効、
シフトアプリ連携ができたら無効に切り替え）をいつにするか。S3の「有効」列で切り替えられます。

## 4. 項目の過不足について

**抜けは見つかりませんでした。** A1〜A7は、サービス提供記録の基本要素（提供日・支援内容・
利用者の状況）と、夜間支援の裏付け（巡回・就寝確認）、実費請求の根拠（食事提供）を
カバーしています。B1〜B5も妥当です。

逆に**削るべき項目もありません**。ただし優先度Bの3項目（入浴・外出・日中活動）は、
Aが安定するまで無効のままにしてください（現状そうなっています）。

**システム外で確認が必要なこと**（AI Uriboでは埋められません）：

- 個別支援計画に**夜間支援の必要性と内容が位置づけられているか**（加算の前提。書類側の話）
- 記録の**保存期間は5年**。AI Uriboは台帳＋Drive＋NASの三重で保持しますが、
  正本である既存アプリ側の保存も忘れずに
- 業務日誌・個別支援記録・実績記録票・出席簿の**相互整合**（AI Uriboの補完データが
  既存アプリに還元されることで支えますが、最終確認は人の目で）

## 5. 「わからない」を週1回まとめて確認する運用について

記録は本来「その都度」求められるため、1週間後に埋めた記録は**後追い記録**になります。
これ自体は問題ありませんが、後から書いたことが分かる形で残すのが安全です。

- AI Uriboは補完台帳に**作成日時**と**情報源**を必ず残すので、後追いであることは追跡できます
- さらに、「わからない」で残った項目は**翌日の夜の確認セットにも自動で載る**設計になっています
  （週次を待たずに、利用者と顔を合わせる夜勤帯にもう一度聞ける）
- 週次ダイジェストは「1週間放置されたものを拾う最後の網」として使ってください
