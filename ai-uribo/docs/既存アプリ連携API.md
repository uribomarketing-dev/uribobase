# 既存アプリ連携API

AI Uriboが埋めた記録（S7_補完台帳）を、既存アプリが**自分で取りに来る**ための口です。
人がスプレッドシートを開いてコピーする作業をなくし、「どこまで取り込んだか」を
台帳側で管理できるようにするためにあります。

---

## 1. 使う前に

| 項目 | 内容 |
|---|---|
| URL | ウェブアプリのURL（`https://script.google.com/macros/s/…/exec`） |
| 秘密キー | スクリプトプロパティ `API_SECRET`。未設定なら `WEBHOOK_SECRET` を使います |
| 認証 | すべての呼び出しに `?k=＜秘密キー＞` を付けます。合わないと何も返しません |

> LINEのWebhookとキーを分けたいときは、スクリプトプロパティに `API_SECRET` を追加してください。
> 分けておくと、片方を作り直しても、もう片方は止まりません。

---

## 2. 取り込みの流れ（この順で呼ぶ）

```
① GET  ?k=＜キー＞&mode=fills          → まだ渡していない記録が返る
② 既存アプリのDBに取り込む
③ POST {"action":"markImported","fill_ids":[…]}  → 取り込めたものに済みを付ける
```

**③まで済ませて初めて「渡した」とみなします。**
②で失敗したら③を呼ばなければ、次の①でまた同じものが返るので、取りこぼしが起きません。

---

## 3. 呼び出し一覧

### `mode=fills` … まだ渡していない補完台帳

| パラメータ | 既定 | 説明 |
|---|---|---|
| `from` / `to` | なし | 対象日で絞る（`YYYY-MM-DD`） |
| `limit` | 500 | 一度に返す件数（最大500） |
| `reviewed` | なし | `1` を付けると「要精査」を除き、確かめ済みだけ返す |

```json
{
  "ok": true, "count": 2, "remaining": 0,
  "items": [
    {
      "fill_id": "FIL000123",
      "対象日": "2026-08-11",
      "対象": "U001",
      "項目名": "在否確認",
      "値": "在宅",
      "情報源": "支援担当者の記録",
      "要精査": false,
      "精査結果": "",
      "記入者staff_id": "STF002",
      "作成日時": "2026-08-12 10:03"
    }
  ]
}
```

- **利用者の氏名は入りません**（`対象` は user_code）。氏名が要るときは `mode=users` を使ってください
- `要精査: true` は「データから推定して埋めた、まだ確かめていない記録」です。
  取り込むかどうかはアプリ側の判断で構いません（`reviewed=1` で除外できます）
- `精査結果` が `食い違い(C01)` のように入っている行は、他の記録と噛み合っていません。
  取り込む前に人の確認をおすすめします

### `mode=users` … user_code と氏名の対応表

```json
{ "ok": true, "count": 2,
  "items": [{ "user_code": "U001", "氏名": "…", "拠点": "清水", "有効": true }] }
```

氏名が出る唯一の呼び出しです。アプリ側で1回だけ呼んで対応表を持ち、
以後は `mode=fills` の user_code だけで突き合わせてください。

### `mode=ping` … 生存確認

```json
{ "ok": true, "時刻": "2026-08-12 10:00", "未取込の補完": 12, "未完了の不足": 3, "テストモード": false }
```

アプリ側の監視に使えます。`未取込の補完` が増え続けていたら、取り込みが止まっています。

### `POST {"action":"markImported","fill_ids":[…]}`

```json
{ "ok": true, "marked": 2 }
```

`marked` は実際に済みを付けた件数です（すでに済みだったものは数えません）。

---

## 4. 呼び出し例

```bash
BASE="https://script.google.com/macros/s/＜デプロイID＞/exec"
KEY="＜API_SECRET＞"

# ① 取得
curl -sL "$BASE?k=$KEY&mode=fills&limit=100"

# ③ 取り込み済みを通知
curl -sL -X POST "$BASE?k=$KEY" \
  -H 'Content-Type: application/json' \
  -d '{"action":"markImported","fill_ids":["FIL000123","FIL000124"]}'
```

> GASのウェブアプリはリダイレクトを返すため、`curl` には **`-L`** を付けてください。

---

## 5. 呼ぶ頻度の目安

1日1回（朝バッチが終わる10:30以降）で十分です。
急ぎで反映したい運用になったら、1時間おきでも負荷にはなりません。

## 6. うまくいかないとき

| 症状 | 見るところ |
|---|---|
| `{"ok":false,"error":"unauthorized"}` | `k=` の値。`API_SECRET`（無ければ `WEBHOOK_SECRET`）と一致しているか |
| HTMLが返る | `-L` が付いていない、またはURLが `/exec` で終わっていない |
| いつも同じ記録が返る | ③の `markImported` を呼べていない |
| `count` が常に0 | まだ補完台帳に記録が無い（朝バッチが動いているか、`mode=ping` で確認） |
