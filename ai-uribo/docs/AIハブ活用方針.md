## 1. AIハブとは何なのか（事実の確認）

| 項目 | 内容 |
|---|---|
| 中身 | **Dockerコンテナ3本**が同時に動く箱：**Home Assistant** ／ **Frigate NVR** ／ **OpenClaw** |
| 頭脳 | **6TOPSのAIチップ**・8GB RAM・32GB eMMC・消費電力約5W |
| ローカルで動く | **物体検出・顔認識**（Frigateが6TOPSで加速）。**サブスク不要** |
| クラウドで動く | 「出来事」の言語化＝**VLM**。ここが有料（AI+） |
| カメラ | SwitchBot製に加え、**RTSP/ONVIFの他社カメラも最大8台**まで束ねられる |

**要するに、この箱は「AIカメラ」ではなく「小さなサーバー」です。**
価値の大半は、有料AIではなく **Frigate＋Home Assistantがローカルで無料で動くこと** にあります。

## 3. うりぼでの使い方（結論）

### 三層に分ける：**事実はFrigate、言葉はAI+、相談はOpenClaw**

```
[常時・無料・ローカル]  Frigate が人の在・不在・動きを検出
                          ↓ MQTT
[場面・700円/月]        AI+ が「配膳している」「横になった」を言葉にする
                          ↓
[Home Assistant]        オートメーションが AI Uribo の Webhook へ POST
                          ↓
[AI Uribo]              「推定・要精査」として記録に入り、翌朝1タップで確定
                          ↓
[人]                    確定させるのは必ず人。AIは"たたき台"まで
```

**OpenClawはこの線の外に置きます。**月8,000回の制限と課金がある以上、
記録の本線に入れると「止まったら記録が止まる」ことになります。
OpenClawの役割は**社員の相談相手**（「先月の食事提供の抜けは？」など）に限定します。

### 効く順（うりぼの実情に合わせた優先順位）

| 順 | やること | 効き方 | 必要なもの |
|---|---|---|---|
| **1** | **夜勤の巡回記録を「思い出して書く」のをやめる**<br>共用部の人の動きを時刻付きで蓄積し、朝「0:15／2:40／4:30に動きあり」と提示 → 1タップで確定 | 夜勤者がいちばん負担に感じている部分。**記憶ではなく事実**になる（監査に強い） | Frigate（**無料**） |
| **2** | **食事提供の記録**<br>配膳シーンを検知 → 時刻付きで「食事提供（推定）」 | 3食×2拠点＝**月180回ぶんの記入**が「確認」に変わる | AI+（700円） |
| **3** | **在否確認**<br>玄関の出入り・在室を検出 | 清水は開閉センサーで実装済み。**玉里はカメラで代替できる** | Frigate（**無料**） |
| **4** | **異常の早期通知**（倒れている等） | 記録ではなく**安全**。ただし下の「やらないこと」を厳守 | AI+（700円） |
| 5 | 社員の相談相手 | 月次の振り返り、機器の一覧 | OpenClaw（269円） |

### やらないと決めたこと（重要）

- **居室内にカメラを置かない。** 共用部だけ。在室・離床は人感／Presenceセンサーで足りる
  （尊厳の問題であり、同意の問題でもあります。センサーなら「数値」しか残りません）
- **カメラで服薬を"記録"しない。** 開放ログ・映像は**声かけのきっかけ**まで。
  記録に残るのは「声をかけた」という支援の事実（既存の設計どおり）
- **診断名・病名・障害区分は扱わない。** 「倒れている」の通知も**見に行く合図**であって、
  健康状態の判断ではありません
- **OpenClawを記録の本線にしない。**（回数制限・課金・単一障害点）
- **映像を家の外に出す量を最小にする。** 台帳に入るのは**言葉だけ**、画像は一切置かない

## 4. 通知の設計（誤検知で現場に見捨てられないために）

VLMの検知は必ず外します。**外れたときに現場が言い返せる形**にしておくのが肝心です。

- 通知は**その拠点の夜勤者1名＋社員**まで。全員には流さない
- 通知には必ず「**違ったら『誤検知』を押してください**」を付ける（AI Uriboに実装済み）
- 誤検知率は**週次ダイジェストに出す**（実装済み）。高ければ条件を緩める／やめる
- **AIの文章をそのまま記録にしない。**「AIはこう見えた」を人が判断する材料として出す
